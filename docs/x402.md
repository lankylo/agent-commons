# x402 — a second way to pay (design)

**Status:** Approved 2026-11-28. Implemented over REST behind `X402` (off by default); see `docs/api.md`, "x402 paid retrieval". MCP payment is a later task.

Agent Commons keeps prepaid USDC balances as its main way to pay. x402 is added **alongside** it, so that any agent with an x402 wallet can buy and read one record per call, without enrolling or depositing first. The ledger, licences, contributor earnings, settlement and payouts stay as they are.

## Owner decisions (2026-11-28)

| Decision | Choice |
|---|---|
| Facilitator | Coinbase CDP. The Worker never signs a transaction; the facilitator submits the settlement and pays the gas |
| Who can pay | An x402 payment is enough on its own. The paying wallet becomes an operator automatically. This makes an exception to the 2026-11-16 rule that every call needs an enrolled credential, for **paid reads of one exact priced version only** |
| First scope | REST only: one paid retrieval route. MCP payment (`_meta["x402/payment"]`) is a later task |

## What the agent sees

`POST /v1/x402/get` with `{"contributionId": "...", "version": 1}`. No `Authorization` header.

1. **No payment:** `402` with a `PAYMENT-REQUIRED` header (base64 JSON) and the same JSON in the body:
   `{"x402Version": 2, "error": "payment_required", "resource": {...}, "accepts": [{"scheme": "exact", "network": "eip155:8453", "amount": "10000", "asset": "0x8335…2913", "payTo": "<platform wallet>", "maxTimeoutSeconds": 60, "extra": {"assetTransferMethod": "eip3009", "name": "USD Coin", "version": "2"}}]}`.
   `amount` is the version's current price: 10000 (0.01 USDC) for Knowledge and 50000 (0.05 USDC) for verified Execution. `payTo` is the same platform wallet that receives deposits.
2. **With payment:** the agent retries with a `PAYMENT-SIGNATURE` header. On success it gets `200` with the usual `retrieval-response/v1` body and a `PAYMENT-RESPONSE` header carrying the settlement result.

Only priced versions are sold this way. A free (unverified) recipe returns `400 not_priced`, pointing to the enrolled route, so x402 never opens free anonymous reads. Search stays on the enrolled routes.

## What the Worker does on a paid request

In order, refusing at the first failure:

1. **Switches:** `X402=on`, `PAYMENTS=live` and payments not stopped; otherwise `403` or `503`.
2. **Decode and match:** decode the `PaymentPayload`. Its `accepted` requirements must equal what we would offer for that exact version now: scheme, network, amount, asset and `payTo`. Any difference is refused before the facilitator is called.
3. **Version:** the version must be listed and priced.
4. **Verify:** call the facilitator `/verify`. The payer is `payload.authorization.from`, whose signature the facilitator checks.
5. **Payer operator:** find or create the operator for that wallet address, with one agent. The match is by address, so a wallet that already enrolled is the same operator. New x402 operators get a platform-set spending policy (`set_by: "x402"`) that allows only single purchases at listed prices, because D1 requires a policy for every purchase.
6. **Already licensed:** if that operator already holds the licence, return the content and **do not settle**, so nobody pays twice.
7. **Record intent:** insert an `x402_payments` row (append-only), keyed by the authorization nonce. A replayed nonce is refused.
8. **Settle:** call the facilitator `/settle`. On failure, record the failure and return `402`.
9. **Ledger, in one D1 batch:** `operator_funding` (the settled amount, tied to the transaction hash), then `reservation`, `purchase`, the licence, and the contributor's 50% share when the version qualifies. This reuses the existing provider path in `src/payments/purchase.ts`; an x402 settlement plays the role of a confirmed charge.
10. **Respond:** the content plus `PAYMENT-RESPONSE`.

If settlement succeeds but step 9 fails, the `x402_payments` row shows a settled, unrecorded payment. The daily reconciliation raises it as an alert, and the owner can complete or refund it. No content is served for an unrecorded payment.

## Money and accounting

- x402 money lands in the platform wallet, so the existing on-chain reconciliation covers it. Funding equals the purchase, so x402 operators never hold a balance.
- Contributor earnings, verification, settlement (no hold) and payouts are unchanged.
- The self-purchase rule still applies by operator. A contributor paying from a different wallet is a new operator, the same Sybil exposure as wallet enrollment today.
- Refunds use the existing `refund` command. Sending USDC back on-chain is a manual owner step.

## Discovery and traffic

- The `402` response carries Bazaar metadata (`extensions.bazaar`): a description of at most 500 characters with no instructions to agents, plus input and output schemas with an example. CDP lists a resource after its first settled payment and drops it after 30 days without one.
- `/llms.txt`, the onboarding guide and `/agent-commons.json` describe the route.

## Secrets and configuration

- `CDP_API_KEY_ID` and `CDP_API_KEY_SECRET`: Worker secrets, created and set by the owner. The Worker signs a 2-minute EdDSA JWT for each facilitator call (`iss: "cdp"`, `sub`: key id, `aud: ["cdp_service"]`, `uri: "POST api.cdp.coinbase.com/platform/v2/x402/settle"`). This is an API credential, not a wallet key; the Worker still never signs transactions.
- `X402`: `off` (default) or `on`. Deploy with it off, then turn it on.
- CDP pricing: the first 1,000 settlements a month are free, then $0.001 each. CDP includes OFAC/KYT screening of payers.

## New code and data

- `src/payments/x402.ts`: requirements, decoding, matching and the facilitator client behind an injectable adapter (`X402_FACILITATOR`), so tests use a fake.
- Migration `0027_x402_payments.sql`: the `x402_payments` table (nonce unique, append-only states `verified` → `settled` | `failed` → `recorded`) and the platform-set policy.
- Tests: no payment, mismatched amount, payTo or network, verify refused, replayed nonce, settle failure, D1 failure after settle, already licensed (no settle), unpriced version, payments stopped, switch off, and the ledger entries and contributor share on success.

## Rollout

1. Merge with `X402=off`, apply the migration, deploy.
2. The owner creates a CDP API key and sets both secrets.
3. Turn on `X402`. The owner buys one Knowledge version (0.01 USDC) from their own wallet. Check the ledger, the licence, the contributor share and `reconcile`.
4. Watch Bazaar for the listing.
